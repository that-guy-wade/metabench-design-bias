# Double-blind protocol for the confirmatory run

Registered 2026-10-25, before any confirmatory session, pool or panel precompute exists. Owner: Seth. Purpose: no agent that builds, repairs, runs or writes about the experiment sees any confirmatory outcome until the analysis is frozen and Seth unblinds. The designers are already blind by construction (pseudonyms, arm-controlled scores view, brief that never names a model). This document blinds the other side.

## 1. Roles, each in a separate session with no shared context

| Role | What it may see | What it may never see |
|---|---|---|
| **Builder** (fresh agent, no pilot knowledge) | pre-registration, scenario, code, synthetic data, pilot sessions only for pipeline repair | any per-model correctness on the main-study pools, any confirmatory session, any endpoint |
| **Pool author** (fresh agent) | item sources, contamination protocol | any model's answers or scores on the items it selects |
| **Runner** (a script, not an agent) | model keys from the managed environment file, the frozen code | nothing; it has no judgement to bias |
| **Health checker** (agent) | the blinded health view (section 4) | raw sessions, raw scores, endpoints |
| **Analysis authors** (two fresh agents, independently) | pre-registration and synthetic data | real data of any kind |
| **Unblinder** | everything | — |

The session that produced the pilot and this document (the one Seth is talking to now) has seen pilot endpoints, including a suggestive identity effect. It is therefore excluded from every role above except writing this protocol and the pre-session amendment. It does not touch pools, panel, analysis code or runner after this file is committed, and it does not read any confirmatory artefact until unblinding.

## 2. Sealing

- The runner writes every confirmatory artefact (sessions, traces, scores, monitor outputs, endpoints) only into `run/sealed/`, encrypted with `gpg` (installed on this box; `age` is an acceptable substitute) to a public key that Seth supplies. The private key never exists on any box. Plaintext is held in process memory and a tmpfs working directory that the runner wipes on exit.
- The panel precompute (per-model, per-sample correctness on the main-study pools) is produced by the runner from the pool files and sealed immediately. The designer interface reads it through the runner process only, and the arm logic (true, sham, inverted, blinded, narrative) is applied inside that process.
- The displayed sham permutations, seeds, prompts, panel list, grader versions and the code hash are written to `prereg/` in plaintext *before* the run and hashed, as the pilot already does. The seeds of the sham permutations are released after unblinding, not before.
- The runner's stdout contains only session ids, exit codes, validity flags, API error counts and timings. No scores, no ranks, no designer text.

## 3. Freezing before data

1. Builder repairs the two logged defects (DIF GLM covariance, CLI identity-arm filter) on synthetic data, with tests that could fail, and extends the panel to the new developers. The pilot's real sessions may be used for pipeline repair only, never for choosing an analysis.
2. Two analysis authors each implement the pre-registered endpoints from `PREREGISTRATION.md` alone, in separate sessions, tested on the shared synthetic generator (null recovers Ψ ≈ 0, injected effects recovered). Both implementations are frozen; both are run by the runner on the sealed data at unblinding. Disagreement between them is reported as a finding, in the many-analysts sense, not reconciled by looking at the data.
3. `prereg/frozen_code.json` records the sha256 of the runner, interface, arm logic, both analysis implementations, the pool files and the prompt templates. Any change after this point is a logged deviation and the affected analysis is exploratory.
4. Only then does the runner start. It runs every registered session once, with no optional stopping and no interim look at outcomes.

## 4. What the health checker is allowed to look at

A physics-style blinded view, generated by the runner, never the raw data:

- evaluee labels replaced by a secret per-run permutation of pseudonyms;
- every score shifted by a hidden per-evaluee offset drawn once per run, so levels and gaps are uninformative;
- arm and identity labels scrambled by a second secret permutation;
- a fixed fraction of decoy sessions (replayed pilot sessions under new ids) mixed in.

On this view the checker may verify: schema validity, parse rates, per-session validity flags, API failure counts, hash matches, time-of-day interleaving across arms, and that each designer has the registered number of sessions. The checker may not compute any statistic across evaluees, arms or designers, and the view makes doing so uninformative anyway. If the checker needs a session replaced (invalid output, API failure), the runner replaces it under the pre-registered replacement rule, once.

## 5. Unblinding ceremony

1. Seth confirms the code hash in `prereg/frozen_code.json` matches the running code and that the registered session count is complete.
2. Seth decrypts `run/sealed/` on a box of his choosing and runs both frozen analysis implementations as scripts. The script writes `REPORT_CONFIRMATORY.md` and the endpoint tables. No agent is in the loop for this step.
3. Only after that file exists may any agent read the data. Everything written afterwards cites the frozen endpoints and labels anything else exploratory.
4. Replication on the held-out designers (section 6) runs after the confirmatory report is written, under the same sealing, and is unblinded separately.

## 6. Pre-session amendment: scale-down with four developers and no fifth family

Keys available: Anthropic, OpenAI, Google, xAI. No open-weights provider. Decided before any confirmatory session; registered here and in `prereg/DEVIATIONS.md`.

- **Designers.** D = 12 from four developers, three per developer, as frozen. Power is the binding constraint (Westfall ceiling), so designer count is not where the study is scaled down.
- **Monitors.** The frozen protocol required a non-designer family. Amended: every session is read by two monitors from the two developers that are neither the designer's nor the same as each other, and monitor recall is calibrated on the scripted hill-climber as in the pilot. Monitor precision is calibrated on the annotated human-audit sample before the run. This is where the study is scaled down.
- **Held-out replication family.** None exists. Amended: replication uses (a) one held-out designer *model* per developer, from an older generation, excluded from the confirmatory twelve, and (b) a held-out *domain* pool. Replication success is defined as before: same sign and overlapping CIs on the primary and S1.
- **Third-party monitor family for the human audit.** Unchanged: human annotators, blind to designer, arm and leader.
